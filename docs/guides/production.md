# เตรียมระบบใช้จริง

ชุดใช้จริงแยกจากชุดทดสอบทุกส่วน: Spreadsheet, โปรเจกต์ Apps Script, โฟลเดอร์ Drive, LINE Login channel และ LIFF app, Cloudflare Pages ใช้ร่วมกันได้เฉพาะ LINE OA (Messaging API channel) และบัญชี SlipOK ห้ามนำข้อมูลสมาชิกจริงไปใส่ชุดทดสอบ

## 1. ตั้งชุดใช้จริง

ทำตาม README หัวข้อ "ตั้งค่าชุดทดสอบ" ทุกข้อ โดยเปลี่ยนเป็นค่าของชุดใช้จริง ดังนี้

| ส่วน | ชุดทดสอบ | ชุดใช้จริง |
|---|---|---|
| Spreadsheet และโปรเจกต์ Apps Script | `ฝากถอนออนไลน์ (ทดสอบ)` | `ฝากถอนออนไลน์` |
| ไฟล์ Script ID | `backend/.clasp.test.json` | `backend/.clasp.prod.json` (คัดลอกจาก `backend/.clasp.prod.example.json`) |
| push โค้ด | `npm run push:test` | `npm run push:prod` |
| LINE Login channel และ LIFF | channel ของชุดทดสอบ | channel ใหม่ของชุดใช้จริง LIFF Endpoint URL ชี้ไปหน้าสมาชิกของชุดใช้จริง |
| ไฟล์ค่าหน้าบ้าน | `apps/*/.env.test` | `apps/*/.env.production` |
| Cloudflare Pages | `npm run pages:test` (โปรเจกต์ `mdh-coop-*-test`) | `npm run pages:prod` (โปรเจกต์ `mdh-coop-member`, `mdh-coop-staff`) |
| Webhook URL ของ LINE OA | URL `/exec` ของชุดทดสอบ | URL `/exec` ของชุดใช้จริง |

LINE OA มี Webhook URL ได้ที่เดียว เมื่อเปลี่ยนเป็นชุดใช้จริงแล้ว การเชิญ LINE OA เข้ากลุ่มจะถูกบันทึกในชุดใช้จริงเท่านั้น ถ้าต้องทดสอบต่อหลังเปิดใช้ ให้ใช้ LINE OA ทดสอบแยกอีกบัญชี

หลังตั้ง Script Properties ครบ ให้รันใน Apps Script editor ตามลำดับ:

1. `checkScriptProperties` (ครั้งแรกจะขออนุญาตสิทธิ์)
2. `createFirstAdministrator`
3. `installDocumentRetentionTrigger`
4. Deploy → New deployment → Web app แล้วนำ URL `/exec` ไปใส่ `.env.production` และ Webhook URL

## 2. ลดความเสี่ยงจาก Gmail ส่วนตัว (ADR 0002)

ระบบและเอกสารทั้งหมดอยู่ใน Gmail ส่วนตัวของเจ้าหน้าที่คนหนึ่ง (เรียกว่า "บัญชีเจ้าของระบบ") ต้องทำทุกข้อก่อนเปิดใช้

- เปิด 2-Step Verification ของบัญชีเจ้าของระบบ ตั้งเบอร์และอีเมลกู้คืนเป็นของสหกรณ์ ไม่ใช่ของส่วนตัว
- แชร์เป็น **Editor** ให้ Gmail ของกรรมการอีก 1 คน (เรียกว่า "ผู้สำรอง"):
  - Spreadsheet `ฝากถอนออนไลน์`
  - โฟลเดอร์ `ฝากถอนออนไลน์ - เอกสาร` ใน Drive
  - โปรเจกต์ Apps Script `ฝากถอนออนไลน์` (Share ในหน้าโปรเจกต์)
- ห้ามแชร์แบบ "ทุกคนที่มีลิงก์" ทั้ง Spreadsheet และโฟลเดอร์ เพราะมีเลขบัตรประชาชนและเอกสารสมาชิก
- เก็บ Channel access token, SlipOK API key และรหัสผ่าน Cloudflare ไว้ในที่เก็บรหัสผ่านของสหกรณ์ ไม่ใช่ในแชต
- ตรวจทุก 3 เดือนว่าผู้สำรองยังเปิดไฟล์ทั้งสามได้

## 3. โอนความเป็นเจ้าของเมื่อเจ้าของระบบลาออก

ทำก่อนวันสุดท้ายของเจ้าของเดิม ระหว่างโอนให้ปิดรับคำขอชั่วคราว (แจ้งสมาชิกผ่าน LINE OA) เพราะ URL ของ Apps Script จะเปลี่ยน

Gmail ส่วนตัวโอนความเป็นเจ้าของไฟล์ข้ามบัญชีส่วนตัวได้เฉพาะไฟล์ใน Drive (เจ้าของใหม่ต้องกดยอมรับ) แต่ web app ของ Apps Script ทำงานในนามบัญชีที่ deploy และ scope `drive.file` เปิดได้เฉพาะไฟล์ที่โปรเจกต์นั้นสร้าง จึงต้อง deploy ใหม่จากบัญชีเจ้าของใหม่ ขั้นตอน:

1. เจ้าของใหม่ (ผู้สำรองหรือเจ้าหน้าที่คนใหม่) ต้องเป็น Editor ของทั้งสามอย่างในข้อ 2 อยู่แล้ว
2. เจ้าของเดิมโอนความเป็นเจ้าของ Spreadsheet, โฟลเดอร์เอกสาร (รวมไฟล์ข้างใน) และโปรเจกต์ Apps Script: Share → เลือกเจ้าของใหม่ → Transfer ownership แล้วเจ้าของใหม่กดยอมรับในอีเมล
3. เจ้าของใหม่ล็อกอิน clasp ด้วยบัญชีตัวเอง (`npx clasp login`) แล้ว `npm run push:prod`
4. ใน Apps Script editor ตรวจ Script Properties ว่ายังอยู่ครบ (รวม `DRIVE_ROOT_FOLDER_ID`, `DRIVE_FOLDER_*`, `WITHDRAWAL_TEMPLATE_DOC_ID`) แล้วรัน `checkScriptProperties` เพื่ออนุญาตสิทธิ์ในนามบัญชีใหม่
5. รัน `installDocumentRetentionTrigger` ใหม่ (trigger ผูกกับบัญชีที่ตั้ง trigger ของเจ้าของเดิมจะหยุดเมื่อบัญชีนั้นหมดสิทธิ์)
6. Deploy → New deployment → Web app (Execute as: Me) แล้วนำ URL `/exec` ใหม่ไปใส่ `.env.production` ของทั้งสองหน้า แล้ว `npm run pages:prod` และเปลี่ยน Webhook URL ใน LINE Developers
7. ทดสอบ: เปิดดูเอกสารเก่าหนึ่งไฟล์จากหน้าเว็บเจ้าหน้าที่ สร้าง PDF ใหม่ของคำขอที่อนุมัติแล้วหนึ่งรายการ และยื่นคำขอฝากทดลองหนึ่งรายการ
8. ถ้าเปิดเอกสารเก่าไม่ได้ (scope `drive.file` ไม่ยอมรับไฟล์ที่โอนมา) ให้หยุดและแจ้งผู้พัฒนา ห้ามลบโปรเจกต์หรือไฟล์ของเจ้าของเดิมจนกว่าข้อ 7 ผ่าน
9. เปลี่ยนรหัสผ่านของผู้ดูแลระบบในหน้าเว็บเจ้าหน้าที่ และปิดบัญชีเจ้าหน้าที่ของเจ้าของเดิม

## 4. LINE OA และโควตาข้อความ

แผนฟรีส่งได้ 300 ข้อความต่อเดือน ไม่พอใช้ ให้สมัครแผนที่เสียเงินก่อนเปิดใช้ (ดูราคาและโควตาปัจจุบันใน LINE Official Account Manager → Settings → Subscription)

ข้อความที่ส่งไปกลุ่ม LINE คิดโควตาตามจำนวนสมาชิกในกลุ่ม (กลุ่มเจ้าหน้าที่ 6 คน = 6 ข้อความต่อการแจ้งเตือนหนึ่งครั้ง) ประมาณการต่อคำขอ:

| คำขอ | ถึงสมาชิก | ถึงกลุ่มเจ้าหน้าที่ |
|---|---|---|
| ฝากเงิน | 3 (ยื่น, อนุมัติ, เสร็จสิ้น) | 1 ครั้ง |
| ถอนเงิน | 4 (ยื่น, ผ่านการตรวจ, อนุมัติ, เสร็จสิ้น) | 2 ครั้ง (ยื่น, รออนุมัติ) |
| บัญชีรับเงิน (ครั้งเดียวต่อบัญชี) | 1 (ผลการตรวจ) | 1 ครั้ง |

ตัวอย่าง: กลุ่มเจ้าหน้าที่ 6 คน เดือนละฝาก 300 และถอน 300 คำขอ ≈ 300 × (3 + 6) + 300 × (4 + 12) = 7,500 ข้อความ ไม่รวมคำขอที่ถูกปฏิเสธ (ข้อความน้อยกว่า) ดูยอดที่ใช้จริงได้ใน LINE OA Manager → Insight หลังเปิดใช้เดือนแรก แล้วปรับแผน ถ้าโควตาหมด ข้อความจะส่งไม่สำเร็จแต่คำขอยังทำงานปกติ (บันทึก `notifyFailed` ใน audit log)

## 5. เช็กลิสต์ก่อนเปิดใช้

ผู้ดูแลระบบดูส่วน "ความพร้อมก่อนเปิดใช้" ในหน้าเว็บเจ้าหน้าที่ และรัน `checkScriptProperties` ใน editor ต้องไม่มีรายการ "ต้องแก้"

- [ ] ตั้งชุดใช้จริงครบตามข้อ 1 และ `checkScriptProperties` ไม่มีรายการที่ยังไม่ได้ตั้ง
- [ ] แชร์ให้ผู้สำรองตามข้อ 2
- [ ] สมัครแผน LINE OA ที่เสียเงิน
- [ ] นโยบายความเป็นส่วนตัวฉบับจริง: แก้ `apps/member/src/privacyPolicy.ts` และเปลี่ยน `PRIVACY_POLICY_VERSION` ใน `shared/api.ts` (เช่น `2026-11`) แล้ว push และ deploy หน้าสมาชิกใหม่
- [ ] Rich Menu ตาม README หัวข้อ 4 และข้อความต้อนรับใน LINE OA Manager (แนะนำให้กดเมนูเพื่อผูกบัญชี)
- [ ] ต้นแบบใบถอนเงิน: ผู้ดูแลระบบเปิดจากหน้าเว็บเจ้าหน้าที่ ตรวจว่าตรงแบบฟอร์ม "ใบถอนเงินออนไลน์" ของสหกรณ์ (ต้นแบบเริ่มต้นจัดตามแบบฟอร์มนี้แล้ว)
- [ ] ยืนยันระยะเวลาเก็บเอกสารกับผู้สอบบัญชี แล้วใส่ `documentRetentionYears` ในชีตตั้งค่า
- [ ] ใส่ `coopReceivingAccount` ในชีตตั้งค่า
- [ ] เพิ่มวันหยุดของสหกรณ์ทั้งปี
- [ ] สร้างบัญชีเจ้าหน้าที่จริง: ผู้ตรวจและผู้อนุมัติอย่างน้อยบทบาทละ 2 คน และเป็นคนละคนกันได้
- [ ] เชิญ LINE OA เข้ากลุ่มเจ้าหน้าที่ แล้วเลือกกลุ่มและใส่ลิงก์หน้าเว็บเจ้าหน้าที่
- [ ] นำเข้าข้อมูลบัญชีเงินฝากจริงครั้งแรก
- [ ] ทดสอบรอบสุดท้าย (ข้อ 6)
- [ ] แจกคู่มือ [เจ้าหน้าที่](staff-manual.md) และ [สมาชิก](member-manual.md)

## 6. ทดสอบรอบสุดท้ายบนชุดใช้จริง

ใช้บัญชี LINE และบัญชีสหกรณ์ของเจ้าหน้าที่ที่เป็นสมาชิกเอง เงินที่ใช้เป็นเงินจริง

1. ผูกบัญชี LINE ตั้ง PIN และเห็นบัญชีเงินฝากของตัวเอง
2. ลงทะเบียนบัญชีรับเงิน ผู้ตรวจอนุมัติ และสมาชิกได้ข้อความแจ้ง
3. โอนเงิน 100 บาทเข้าบัญชีสหกรณ์ แล้วยื่นคำขอฝากพร้อมสลิปจริง ต้องขึ้น สลิปถูกต้อง
4. ยื่นคำขอถอนเงิน 1,000 บาท ผู้ตรวจตรวจผ่าน ผู้อนุมัติ (คนละคน) อนุมัติ แล้วเปิด PDF ใบถอนเงินดูว่าภาษาไทยและลายมือชื่อถูกต้อง
5. export รายการที่อนุมัติแล้วเปิดไฟล์ .xlsx ได้ บันทึกเข้าระบบหลัก แล้วปิดคำขอทั้งสองเป็น เสร็จสิ้น
6. ตรวจว่าสมาชิกได้ข้อความทุกขั้น กลุ่มเจ้าหน้าที่ได้ข้อความแจ้งเตือน และ audit log มีการเปิดดูเอกสารครบ
