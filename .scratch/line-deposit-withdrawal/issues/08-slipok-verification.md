# 08: ตรวจสลิปด้วย SlipOK

**What to build:** เมื่อสมาชิกแนบสลิปในคำขอฝากเงิน ระบบตรวจกับ SlipOK ทันที

- ไม่รับสลิปที่ไม่ได้โอนเข้า**บัญชีรับโอนของสหกรณ์** (กรุงไทย) หรือสลิปที่เคยใช้แล้ว
- ถ้ายอดหรือเวลาไม่ตรงกับที่กรอก ระบบแสดงค่าจากสลิปให้สมาชิกยืนยัน
- ถ้า SlipOK ใช้ไม่ได้ ระบบยังรับคำขอไว้
- สลิปที่ผ่านทุกข้อติดป้าย **สลิปถูกต้อง** ให้ผู้ตรวจเห็น

**Blocked by:** 07 - คำขอฝากเงิน

**Status:** ready-for-agent

- [ ] ตัวตรวจสลิปตัวจริงเรียก SlipOK โดยอ่าน API key และหมายเลขบัญชีรับโอนของสหกรณ์จาก Script Properties
- [ ] `checkSlip` คืนผลตรวจและค่าจากสลิป (ยอด, วันเวลา, เลขอ้างอิง) โดยไม่สร้างคำขอ และเก็บผลไว้ใน cache โดยใช้แฮชของไฟล์เป็น key
- [ ] ผู้รับไม่ใช่บัญชีรับโอนของสหกรณ์: ไม่รับ พร้อมเหตุผลภาษาไทย
- [ ] เลขอ้างอิงซ้ำกับคำขอที่ไม่ได้อยู่ในสถานะยกเลิกหรือปฏิเสธ: ไม่รับ และตรวจซ้ำอีกครั้งภายใต้ lock ตอน `submitDepositRequest`
- [ ] ยอดไม่ตรง หรือเวลาคลาดเกิน ±10 นาที: หน้า LIFF แสดงค่าจากสลิปให้ยืนยัน แล้วคำขอใช้ค่าจากสลิป
- [ ] SlipOK ไม่ตอบหรืออ่านสลิปไม่ได้: รับคำขอ และผลตรวจเป็น ยังไม่ตรวจสลิป
- [ ] ผ่านทุกข้อ: ผลตรวจเป็น สลิปถูกต้อง และบันทึกเลขอ้างอิงสลิป
- [ ] `submitDepositRequest` ใช้ผลจาก cache และไม่เรียก SlipOK ซ้ำ
- [ ] หน้าเว็บเจ้าหน้าที่แสดงป้ายผลตรวจสลิปทั้งในคิวและหน้ารายละเอียด
- [ ] การทดสอบที่ตัวรับคำสั่งครอบคลุม (ใช้ตัวตรวจสลิปปลอม): ผ่าน, ผู้รับผิด, เลขอ้างอิงซ้ำ, เลขอ้างอิงซ้ำกับคำขอที่ถูกปฏิเสธแล้วยังใช้ได้, ยอดไม่ตรง, เวลาไม่ตรง, SlipOK ล่ม, ใช้ผลจาก cache
